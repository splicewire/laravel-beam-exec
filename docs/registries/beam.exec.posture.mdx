# Board posture

`beam.exec.posture` holds the **posture contributors**: the sources the board asks how the estate
stands. Each contributor returns a list of signals, and each signal is a named check with a status
of pass, warn or fail and a sentence saying why. Two cards on the board count them: **Posture**
shows the worst status and how many checks pass, warn and fail, and **Risk** adds the failing
checks to the suspended tenants and failed provisioning it already sees.

Out of the box there is one contributor, `doctor`: the readiness audits your host and its packages
register for `splicewire:beam:doctor`. Every finding those audits report becomes one signal, with
its status unchanged. An installed package that knows something the doctor does not, such as
whether subscribers have met their compliance requirements, adds its own contributor next to it.

## Who fills it

The exec package registers `doctor` through its config default. A host lists its contributors in
`config('beam.exec.posture')`, as a map of key to class:

```php
// config/beam/exec.php
'posture' => [
    'doctor' => \Splicewire\Beam\Exec\Posture\Contributors\DoctorPostureContributor::class,
    'ledger' => \App\Board\LedgerPosture::class,
],
```

A map you declare replaces the default, so keep `doctor` in it if you want the readiness audits on
the board.

A package contributes from its own service provider. Register when the registry is first built,
naming it only by its class string, so a host that does not install the exec package pays nothing:

```php
use Splicewire\Beam\Exec\Posture\PostureRegistry;

public function register(): void
{
    $this->app->afterResolving(PostureRegistry::class, function (PostureRegistry $posture) {
        if (! $posture->has('ledger')) {
            $posture->register('ledger', LedgerPosture::class);
        }
    });
}
```

The dependency points from your package down to exec. Exec never names a contributor it does not
ship.

## Writing a contributor

A contributor implements `PostureContributor` and returns its signals:

```php
use Splicewire\Beam\Exec\Posture\PostureContributor;
use Splicewire\Beam\Exec\Posture\PostureSignal;

final class LedgerPosture implements PostureContributor
{
    public function signals(): array
    {
        $orphans = LedgerEntry::query()->whereNull('account_id')->count();

        return [
            $orphans === 0
                ? PostureSignal::pass('ledger.orphans', 'Every entry names an account.')
                : PostureSignal::fail('ledger.orphans', "{$orphans} entries name no account."),
        ];
    }
}
```

- **`pass`**, **`warn`** and **`fail`** are the doctor's own three words. A doctor `Finding`
  converts with `PostureSignal::fromFinding()`.
- **`unmeasured`** is for a check that had nothing to look at: no rows yet, or a sweep that has
  never run. It is counted as unmeasured, never as passing, so an empty estate does not read as a
  clean one.
- Leave the signal's source empty. The board stamps each signal with the key its contributor is
  registered under.

A contributor is resolved from the container and may read the database. It runs on a board
request, so keep it cheap or serve a stored reading. The doctor contributor never runs the audits on
a board read: it serves the last report, with the time it was measured (the posture card shows its
age), and queues a refresh when there is none or it is older than `beam.exec.doctor_posture_ttl`
seconds (900 by default). Before the first report lands, the posture reads unmeasured. 0 runs the
audits inline on every read. `splicewire:beam:exec:refresh-posture` refreshes the report now, for a
schedule or a deploy step. A contributor that
throws shows on the board as one failing `contributor-errored` signal, and every other contributor
still reports.

Cards never call a contributor. They read `posture()` on the board source they are handed, which
is how the lens decides what posture means: a synthesized scenario models customers and money, not
the estate, so it has no posture, and the posture card reads unmeasured under it rather than put
real audit results under a "Synthesized" watermark.

The [**duplicate-key policy**](/beam/docs/foundations/registries#key-policies) is **reject**: two
contributors under one key would silently drop a source of posture from the board. To stand one
contributor in for another, configure it under that key instead.
